# 工作区根仓库常驻需求规格

## 背景

`Changed Repositories` 当前默认使用 `pinned` 扫描模式。该模式只根据
`scmRepositoryFilter.pinnedRepositories` 创建手动固定的仓库对象，因此工作区根目录本身即使是 Git
仓库，只要没有被手动固定，也不会出现在列表中。

像 `kfc-ordering-preorder` 这样的工程，工作区根目录是主工程 Git 仓库，`originSource` 下还有大量独立
的嵌套仓库。用户固定任意嵌套仓库后，仍需要主工程仓库始终显示，以便查看和操作主工程改动。

## 范围（In Scope）

- 每个 VS Code 工作区根目录只要自身包含 `.git` 目录或 `.git` 文件，就识别为主工程仓库。
- 主工程仓库在 `pinned` 和 `all` 两种模式下都常驻 `Changed Repositories`，无论是否有改动、是否配置了手动固定仓库。
- 主工程仓库作为自动识别项显示为普通仓库，不显示 Pin 图标，也不提供 Unpin 操作。
- 多根工作区中，每个自身存在 `.git` 的工作区根目录都按相同规则常驻。
- 复用现有工作区根浅扫描能力，避免 `pinned` 模式为此需求触发递归扫描。

## 非目标（Out of Scope）

- 不向工作区父目录查找 Git 仓库；工作区根目录自身没有 `.git` 时不误判为主工程。
- 不改变手动固定仓库的配置格式、历史记录或导入流程。
- 不递归推断哪个嵌套仓库具有业务上的“主工程”含义。
- 不修改 Changed Files、Git 操作或 Git 状态解析行为。
- 不新增配置开关；工作区根仓库常驻是默认行为。

## 核心场景

### 默认 pinned 模式、没有手动固定仓库

1. 扩展浅扫描工作区根目录。
2. 工作区根目录存在 `.git` 时创建或复用主仓库对象。
3. 即使主仓库干净，`Changed Repositories` 仍显示该普通仓库。

### pinned 模式固定嵌套仓库

1. 用户手动固定 `originSource/kfc/stores` 等嵌套仓库。
2. Provider 合并“主仓库根目录 + 手动固定仓库根目录”，路径规范化后去重。
3. 主仓库与固定嵌套仓库同时常驻；只有嵌套仓库显示 Pin 语义。

### all 模式与异步递归扫描

1. 初始化先浅扫描并展示工作区根仓库，再后台递归扫描嵌套仓库。
2. 递归扫描完成后，可见集合为“有改动仓库 ∪ 手动固定仓库 ∪ 主仓库”。
3. 主仓库零改动时仍保留；无改动且未固定的其他嵌套仓库仍按现有规则隐藏。
4. 从 `all` 切回 `pinned` 时，过期异步结果不得覆盖新的“主仓库 + 手动固定仓库”集合。

### 非 Git 工作区根目录

工作区根目录没有 `.git` 时不创建主仓库对象；如果也没有手动固定仓库或其他改动仓库，则继续显示现有
空态提示。

## 验收标准

- `pinned` 模式下，工作区根目录存在 `.git` 且固定列表为空时，根仓库仍由 `getChildren()` 返回。
- `pinned` 模式下，工作区根仓库和手动固定嵌套仓库都为干净状态时，两者都由 `getChildren()` 返回。
- 主仓库条目的 `contextValue` 为普通仓库语义，不等于 `pinnedRepository`；手动固定仓库仍保持 pinned 语义。
- `all` 模式下，干净主仓库和有改动嵌套仓库同时显示；干净且未固定的其他嵌套仓库不显示。
- 工作区根目录无 `.git` 时，Provider 不创建或展示该根仓库。
- 多根工作区只展示自身存在 `.git` 的根目录；结果按规范化绝对路径去重。
- 根仓库浅扫描失败时记录现有日志，并继续处理可解析的手动固定仓库。
- 模式切换或异步扫描存在竞态时，旧代际结果不能把非当前模式仓库写回列表。
- `npm run check`、`npm test`、`npm run harness:doctor` 和 `git diff --check` 均退出码为 0，且 `npm test` 报告 `pass > 0`。

## 风险与权衡

- 主仓库自动识别与手动 Pin 必须保持两套语义，否则会错误出现 Pin 图标、Unpin 命令或历史记录；实现应让“是否常驻”和“是否手动固定”分别判断。
- `pinned` 模式增加一次工作区根浅扫描，但只检查 `.git` 标记，不递归进入大型目录，初始化成本可控。
- 工作区根目录可能被删除或失去权限；扫描失败时采用单目录降级，不能阻断其他仓库刷新。
- 如果用户历史配置已经包含工作区根路径，条目仍应以普通主仓库语义展示，避免通过插件静默改写用户设置。
- 多根工作区与路径规范化存在重复风险，所有主仓库、固定仓库和扫描仓库合并前必须使用同一绝对路径 key。
